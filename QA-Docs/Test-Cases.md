## Блок 1. Создание заказа

### TC-01. Создание заказа с валидными данными ✅
**Предусловие:** открыта главная страница, выбран СЦ «Уфа».
**Шаги:**
1. Нажать «Новый заказ».
2. Заполнить номер заказа: `UF-9999`.
3. Заполнить грузоместо: `CN-99999`.
4. Выбрать отгрузку: `Уфа`, поставку: `Самара`.
5. Статус: `В процессе`. Проблема: `Дубль`.
6. Нажать «Создать».
**Ожидаемый результат:** редирект на главную. В таблице появился заказ `UF-9999`. В БД (проверено через DBeaver) появилась запись с датой в UTC. Заказ принадлежит СЦ «Уфа».
**Фактический результат:** всё работает как задумано. Заказ в таблице, запись в БД есть, дата в UTC. Кейс пройден.

### TC-02. Попытка создать заказ с пустыми полями ✅
**Шаги:**
1. Открыть форму создания.
2. Ничего не вводить (или заполнить только одно поле).
3. Нажать «Создать».
**Ожидаемый результат:** форма не отправляется на сервер (блокируется валидацией на клиенте). Под обязательными полями — красные сообщения. Запись в БД не создаётся.
**Фактический результат:** валидация сработала корректно, форма не ушла на сервер, поля подсветились. Запись не создалась. Кейс пройден.

### TC-03. Ввод слишком длинного номера заказа ✅ (с замечанием)
**Шаги:**
1. Открыть форму создания.
2. Ввести в номер заказа строку из 100 символов (`AAAA…`).
3. Заполнить остальные поля и нажать «Создать».
**Ожидаемый результат:** либо форма не даёт отправить (ограничение по длине), либо заказ создаётся и таблица не разъезжается при отображении.
**Фактический результат:** ограничения на длину в модели нет, заказ создался. Текст переносится, вёрстка не ломается. Кейс пройден, но замечание: `MaxLength` стоит добавить (в планах).

**Фактический результат:** работает корректно, отображается только нужный заказ. Кейс пройден.

## Блок 4. Скрытие и восстановление

### TC-10. Скрытие заказа ✅
**Шаги:**
1. На главной найти любой заказ.
2. Нажать на жёлтую кнопку «глазик» (скрыть).
**Ожидаемый результат:** заказ исчезает из основной таблицы, появляется уведомление «Заказ скрыт». В БД флаг `IsHidden = true`.
**Фактический результат:** заказ исчез, уведомление появилось, флаг в БД переключился. Кейс пройден.

### TC-11. Восстановление заказа ✅ (после фикса)
**Предусловие:** есть скрытый заказ (из TC-10).
**Шаги:**
1. Открыть «Скрытые заказы».
2. Найти нужный заказ.
3. Нажать «показать» (зелёный глазик).
**Ожидаемый результат:** заказ возвращается в основной список, в БД `IsHidden = false`.
**Фактический результат:** первый прогон упал — заказ пропадал со страницы скрытых, но на главную не возвращался (BUG-04). После исправления логики переключения кейс проходит. Пройден после фикса.

**Шаги:**
1. Нажать на красную кнопку «корзина» у любого заказа.

**Фактический результат:** первый прогон упал — после «ОК» вылетала ошибка 400 Bad Request (BUG-05). При контрольном прогоне на актуальной сборке ошибка не воспроизводится: антифоржери-токен в форме на месте, удаление проходит корректно. Кейс пройден.

### TC-14. Отмена удаления заказа ✅

**Фактический результат:** при «Отмене» ничего не происходит, заказ на месте. Кейс пройден.

## Блок 7. Негативные и граничные сценарии

### TC-15. Создание двух заказов с одинаковым номером ⏳
**Предусловие:** в системе уже есть заказ с номером `UF-9999`.
**Шаги:**
1. Открыть форму создания.
2. Ввести номер заказа `UF-9999` (уже существующий).
3. Заполнить остальные поля и нажать «Создать».
**Ожидаемый результат:** либо форма не даёт отправить (проверка на дубликаты), либо выводится понятная ошибка «Заказ с таким номером уже существует». Сайт не падает с 500-й.
**Фактический результат:** на проверке. Если в БД нет уникального индекса на `OrderNumber`, дубль создастся — тогда завожу баг и фикс (уникальный индекс + проверка в контроллере) в следующей итерации.

### TC-16. Смена СЦ во время активного поиска ⏳
**Предусловие:** выбран СЦ «Уфа», в поиске введено `UF`.
**Шаги:**
1. Не очищая поле поиска, переключить СЦ в шапке на «Грибки».
2. Посмотреть на результат.
**Ожидаемый результат:** поиск либо сбрасывается (показаны все заказы «Грибков»), либо применяется к заказам нового СЦ. Не должно быть каши из заказов двух СЦ одновременно.
**Фактический результат:** на проверке. Смотрю, как ведёт себя URL: если параметр поиска подтягивается со старым контекстом — заводить баг.

### TC-17. Открытие формы редактирования чужого заказа по прямому URL ⏳ (известная проблема)
**Шаги:**
1. Находясь в СЦ «Уфа», скопировать ссылку на редактирование заказа из «Грибков» (например, `/Orders/Edit/Грибки/5`).
2. Вставить в адресную строку и нажать Enter.
**Ожидаемый результат:** система либо не даёт открыть чужой заказ, либо корректно переключает контекст. Не должно быть ситуации, когда заказ редактируется, но сохраняется «не туда».
**Фактический результат:** сейчас `Edit` не проверяет совпадение `UserSC` заказа с текущим СЦ — теоретически можно открыть чужой заказ, зная его ID. Проблема осознанно отложена: нормальное решение — авторизация и роли (см. «Планы» в README). Зафиксировано как известное ограничение.

### TC-18. Кнопка «Назад» в браузере после создания заказа ✅ (с замечанием)
**Шаги:**
1. Создать любой заказ.
2. Нажать «Назад» в браузере.
**Ожидаемый результат:** браузер не должен предлагать повторную отправку формы. Если предлагает — терпимо для MVC, но не для прода.
**Фактический результат:** стандартное поведение — Chrome спрашивает «Подтвердить повторную отправку формы». Для учебного проекта приемлемо (POST → редирект → кэш браузера — тема отдельной оптимизации). Кейс пройден с замечанием.

### TC-19. Отображение очень длинных значений в таблице ✅ (с замечанием)
**Предусловие:** есть заказ с длинным номером грузоместа (50+ символов).
**Шаги:**
1. Открыть главную страницу.
2. Найти этот заказ в таблице.
**Ожидаемый результат:** текст переносится или обрезается с многоточием (`text-overflow: ellipsis`), таблица не разъезжается, кнопки действий не уезжают.
**Фактический результат:** на разрешении 1366x768 при длинном тексте таблица скроллится горизонтально. Не баг, но UX-момент — можно поправить стилями. Кейс пройден с замечанием.

### TC-20. Скрытый заказ не находится поиском ⏳
**Предусловие:** заказ `UF-9999` скрыт.
**Шаги:**
1. На главной ввести в поиск `UF-9999`.
2. Нажать «Поиск».
**Ожидаемый результат:** заказ не найден (он скрыт и лежит в другой вкладке). Поиск не должен «вытаскивать» скрытые заказы в основной список.
**Фактический результат:** в контроллере фильтр `!o.IsHidden` применяется до поиска, скрытые попадать не должны. Перепроверить при регрессе.
