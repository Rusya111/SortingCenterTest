# План тестирования (Test Plan)

Решил потестировать свой же проект перед тем, как показывать его кому-то. Цель - проверить, что основная логика работает, ничего не падает и не ломается при нестандартном вводе.

## 1. Что будем тестировать (Scope)

В целом проверяем весь основной функционал, который есть на сайте:

- Главную страницу (таблица заказов). Проверить что грузятся только заказы текущего города и без скрытых.
- Поиск. Проверить как ищет по номеру заказа и по грузоместу.
- Создание заказа. Валидация полей, сохранение в БД, редирект.
- Редактирование. Что данные подтягиваются и сохраняются.
- Удаление и скрытие (soft delete). Что заказ пропадает из списка, но если скрыт - то лежит во вкладке скрытых.
- Переключение города в шапке.

**Что НЕ тестируем (пока что):**
- Нагрузку (не на чем гонять).
- Безопасность глубоко (кроме базовой проверки CSRF токенов).
- Мобильную версию (смотрел только на компе, в браузере Chrome).

## 2. Как тестируем (Подход)

- **Функциональное (ручное):** просто хожу по страницам и проверяю сценарии из чек-листа.
- **Тест-дизайн:** буду использовать классы эквивалентности и граничные значения для полей ввода (особенно для номеров заказов и поиска). Попробую поломать сайт пустыми строками и очень длинным текстом.
- **Черный ящик:** смотрю только на интерфейс, код во время тестирования не читаю (чтобы поймать баги, которые увидит реальный юзер).

## 3. Что нужно для старта (Окружение)

- ОС: Windows 10
- Браузер: Chrome (последняя версия)
- БД: PostgreSQL (локально, через DBeaver иногда смотрю что записалось)
- Инструменты: DevTools (вкладка Network, чтобы смотреть какие запросы улетают, и Console на ошибки).

## 4. Когда заканчиваем (Критерии выхода)

Тестирование считаю законченным, когда:
1. Прошел все пункты из чек-листа.
2. Проверил все написанные тест-кейсы.
3. Все найденные баги записал в отдельный файл (Bug-Reports).
4. Критические баги (которые ломают основной сценарий) исправлены или задокументированы, если фикс отложен.

## 5. Риски

- Могу что-то упустить, так как тестирую сам. Глаз "замыливается" на свой код.
- Тестовые данные в БД могут закешироваться, надо будет чистить перед некоторыми проверками.
